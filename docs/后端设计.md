# 奶爸机后端设计

## 运行形态

当前版本采用本地生产化路线：Electron 主进程启动 Node HTTP API，页面通过 `fetch` 调用本地接口。数据写入 Electron `userData/data/naibaji-db.json`，保留 Windows 打包简单性，不引入原生数据库依赖。

## 模块

- `backend/src/server.js`：本地 API 入口，提供健康检查、批次、每日记录、推荐、审批、执行、导出、模型注册表和场景状态接口。
- `backend/src/storage/jsonDatabase.js`：表式 JSON 数据库。
- `backend/src/repositories`：批次、每日记录、称重样本、推荐日志、审批日志、执行日志、场景状态、模型注册表和审计日志仓储。
- `backend/src/services`：业务闭环服务。
- `backend/src/models`：复用根目录 `feeding-model.js` 和 `v5lite-model.js`。

## 核心闭环

```text
Batch
  -> DailyRecord
  -> RecommendationLog
  -> ApprovalLog
  -> ExecutionLog
  -> BatchLearning
  -> SceneState
```

推荐公式：

```text
FinalMilk = BaseMilk * WeightCorrection * RiskAdjustFactor
```

早期限制：

- 自动推荐允许下调。
- 上调必须进入人工审批。
- 三等级字段只做弱学习。
- 有称重锚点时估重置信度更高。
- 每条推荐记录模型版本、风险、估重、阻断原因和推荐奶量。

## 主要接口

- `GET /api/health`
- `GET /api/batches?includeRecords=1`
- `POST /api/batches`
- `GET /api/batches/:id`
- `PUT /api/batches/:id/snapshot`
- `POST /api/batches/:id/records`
- `GET /api/batches/:id/recommendations`
- `POST /api/batches/:id/complete`
- `GET /api/batches/:id/export`
- `POST /api/recommendations/:id/approve`
- `POST /api/recommendations/:id/execute`
- `GET /api/model/registry`
- `GET /api/scene-states/:sceneId`

## 前端兼容策略

页面仍保留 localStorage fallback。启动时如果本地 API 可用，会先把旧 localStorage 批次迁移到后端，再从后端回填；之后每次保存当前批次，都会同步完整 snapshot 到后端并重新计算推荐日志。
